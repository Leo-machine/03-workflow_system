【一】系统目标
把 Word 里的"物理机资源申请流程"变成数据驱动的活地图：每个环节回答
归谁办 / 做什么交什么 / 在哪些系统怎么操作（带链接、依据）。
M1 核心：管理模式改人真正落库，刷新后所有人看到同一份最新，且修改留痕。

三层数据结构：
- 流程定义层：环节顺序 + 环节对应岗位（很少变）
- 岗位→人映射层：每个岗位当前是谁（管理员维护，改一处处处同步）
- 人员层：人的信息（以后接内网通讯录）

【四】数据表（终版）
persons：      id PK, name, dept, title, contact(可空), source(manual/directory), active
roles：        id PK, code 唯一, name
assignments：  role_id PK(兼FK→roles), person_id FK→persons, updated_by, updated_at
flows：        id PK, name, description, status(draft/published), updated_by, updated_at
steps：        id PK, flow_id FK, code, name, task, order_index
step_roles：   联合主键 (step_id, role_id)，均 FK
guide_items：  id PK, step_id FK, order_index, system_name, url(可空),
               image_path(可空), action_text, note(可空)
change_logs：  id PK, entity_type, entity_id, field, old_value, new_value,
               old_name, new_name（姓名快照，可空；首次设岗 old_* 为 NULL）,
               changed_by, changed_at；只插不改不删
users：        id PK, username 唯一, password_hash, role(viewer/admin)

【五】接口清单（终版）
POST /auth/login            公开   {username,password} → {access_token, user:{username,role}}
GET  /auth/me               登录   当前用户
GET  /flows                 登录   流程列表
GET  /flows/{id}            登录   流程+环节(按 order_index)+岗位解析成当前责任人+指引(按 order_index)
GET  /persons               登录   全部人员（下拉用）
PUT  /assignments/{role_id} admin  {person_id} → 语义见下
GET  /change-logs           admin  倒序，limit/offset 分页

PUT /assignments/{role_id} 语义：
- 换成不同的人：一个事务内更新 assignments + 插一条 change_log
  （含 old/new person_id 和姓名快照），返回 {role_id, person_id, changed:true, change_log_id}
- 同人（no-op）：返回 {role_id, person_id, changed:false, change_log_id:null}，不写日志
- person_id 不存在 → 422；非 admin → 403；未登录 → 401

GET /change-logs 单条结构（前端直接渲染）：
{ id, entity_type:"assignment", entity_id, field:"person_id",
  old_value, new_value, old_name, new_name,
  role_name, changed_by, changed_at }
