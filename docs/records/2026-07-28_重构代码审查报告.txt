P0 问题（建议本轮修）
--------------------------------------------------------------
P0-1 管理后台与前台未隔离
  现状：流程设计器(/flows/:id/edit)、管理模式、变更记录全部与只读界面
  同一个 SPA bundle、同一路由空间，仅靠各组件内部 isAdmin 判断隐藏；
  dnd-kit 等管理端代码打进所有用户的产物里；App.tsx 无集中路由守卫。
  底线安全由服务端 require_admin 保证（这点是对的），但 UI 层缺纵深：
  新增 admin 页面时漏判一次就是事故。
  建议（两档）：
  A. 轻量：路由层集中守卫 <RequireAdmin> 包裹 /flows/:id/edit 等管理路由；
     管理端组件 React.lazy 分包，viewer 不下载管理代码。
  B. 彻底：admin 拆独立入口（vite 多页 admin.html），nginx 可对 /admin
     单独加访问控制（IP 白名单/额外认证）。迁内网前建议做到 B。

P0-2 变更记录面板读不懂 flow 类日志（实测确认）
  实测：库里已有 8 条 entity_type=flow 的日志（你试设计器产生的），
  但 ChangeLogPanel 列写死「岗位/原责任人/新责任人」，flow 日志显示为
  岗位=—、原责任人=—、新责任人=流程名 —— 语义错乱。
  且 _add_flow_log 的快照语义不对：改名时 old_name 恒为 None、
  new_name 恒为流程新名，看不出「从谁改成谁」，违背留痕初衷。
  建议：面板按 entity_type 分行渲染（assignment 行 / flow 行）；
  后端 name 变更记 old_name=旧名、new_name=新名。

P0-3 viewer 可直达 draft 流程详情（实测 HTTP 200 确认）
  导航页把 draft 显示为「建设中」暗示不可见，但 GET /flows/{id}
  不分状态，viewer 直接输 /flows/2 即可看 draft 内容。
  建议：后端 GET /flows/{id} 对非 admin 且 draft 返回 404（不暴露存在性）。

P0-4 PUT /flows/{id}/definition 无 no-op 判断，每次保存必写日志
  违背你自己定的「无变化不记日志」原则。
  建议：对比新旧定义（规范化序列化后 diff），无变化不写日志、
  响应带 changed 标记（与 assignments 语义对齐）。

P1 问题（建议排期修）
--------------------------------------------------------------
P1-5 published 流程可直接改定义，全员即时生效，无审批无版本。
  产品决策点：建议「published 冻结定义，先回 draft 再改」或
  「编辑生成新 draft 版本，发布时替换」。需要你拍板。
P1-6 PATCH /flows 一次改多字段产生多条日志但只返回最后一个 id。
  建议要么合并为一条（fields 逗号连接），要么返回 id 列表。
P1-7 slug 全链路未使用：后端生成 slug、前端路由却全用数字 id。
  建议二选一：URL 改用 slug（/flows/phys-server-apply，可读可分享）
  或删除该字段。
P1-8 隐性耦合点（"前后端不分离"的真实来源）：
  - 前端硬编码 ICONS 映射/BUS 编号 vs 后端 seed 的 icon 字符串；
  - types.ts 手写对齐 schemas.py，无生成/校验机制，已出现漂移
    （DomainFlow.slug 前端可选、后端可空 —— 本次恰好兼容）；
  - react-router-dom 用了 ^7.18.1，其余依赖全部锁死版本，风格不一致
    （有 package-lock 兜底，但建议统一锁死）。
P1-9 GET /flows 旧列表接口残留：前端已不用，返回结构无 domain 信息。
  建议删除或加 domain 过滤参数保留。
